## Contradictions between files

1. **Duplicate save: 409 vs 200.**
   - `001-bookmarks-api/spec.md:15` "Reject it with a conflict error that includes the existing bookmark's identifier"
   - `001-bookmarks-api/spec.md:44-46` "...the user receives a conflict error that includes the existing bookmark's identifier."
   - `001-bookmarks-api/research.md:39-40` "if nothing is returned, look up the existing row and raise a duplicate error carrying its id."
   - `001-bookmarks-api/research.md:87` "`duplicate_url` (409, `details.existing_id`)"
   - `001-bookmarks-api/contracts/openapi.yaml:129` "enum: [validation_error, not_found, duplicate_url, internal_error]"
   - `001-bookmarks-api/quickstart.md:39` "409 `duplicate_url`, `details.existing_id` = id from step 1"
   - The other side: `002-idempotent-duplicate-save/spec.md:116` "A duplicate save never produces a conflict error any more." and `002-idempotent-duplicate-save/quickstart.md:31` "No step returns 409 any more."
   - 002 says it wins (`002-idempotent-duplicate-save/spec.md:17-18`), and `002-idempotent-duplicate-save/plan.md:114-126` lists each replaced 001 line. The cited line numbers match the 001 files.
2. **Paging inside the 001 spec: offset vs token.**
   - `001-bookmarks-api/spec.md:18` "Return pages: 20 per page by default, up to 100 per page, using a limit and an offset, plus the total count."
   - The other side: `001-bookmarks-api/spec.md:23` "The offset option is removed, and a request that still sends it gets a validation error that points to the token."
   - The later clarification (constitution v1.1.0) replaces the earlier one, but line 18 was left as written.
3. **Paging in 001 tasks.md: offset vs cursor.**
   - `001-bookmarks-api/tasks.md:81-82` "`GET /bookmarks` returns saved bookmarks newest first with `total`, `limit` and `offset`."
   - `001-bookmarks-api/tasks.md:93` "Add `BookmarkPage {items: list[Bookmark], total, limit, offset}`"
   - The other side: `001-bookmarks-api/contracts/openapi.yaml:113` "required: [items, total, limit, next_cursor]"
   - tasks.md marks the old tasks as history (`001-bookmarks-api/tasks.md:84-85` "T017-T020 built offset paging, which Principle VI now forbids... these tasks are kept as history"), and T032-T034 at lines 206-208 replace them with cursors.
4. **Trailing slash: one or several (minor wording).**
   - `001-bookmarks-api/spec.md:16` "trailing slash on the path removed" (singular)
   - The other side: `001-bookmarks-api/research.md:49` "strip one or more trailing slashes from the path" and `001-bookmarks-api/data-model.md:48` "Remove trailing slashes from the path."
   - The spec does not settle whether a path ending in several slashes is the same link.
5. **Tag limit wording (possible ambiguity, not a clear conflict).**
   - `001-bookmarks-api/spec.md:49` rejects a save "with more than 10 tags".
   - The other side: `001-bookmarks-api/contracts/openapi.yaml:99-100` "At most 10 tags after normalization ... so 11 raw tags that collapse to 10 are accepted."
   - Whether "more than 10" means raw or normalized tags is unclear in the spec. `001-bookmarks-api/tasks.md:201` (T030) aligned the contract to "after normalization".
