## Contradictions and inconsistencies found

1. **Old duplicate rule still in spec.md, marked as superseded.** `spec.md:15` says "Reject it with a conflict error that includes the existing bookmark's identifier" and goes on "*(Superseded 2026-10-24 by the change request below; see FR-004.)*". The current rule is at `spec.md:165-166`: "MUST NOT be rejected: it MUST return the existing bookmark unchanged with HTTP 200 OK". The research.md history note keeps the old behavior too: `research.md:59-60` "raised a duplicate error ... mapped to 409 `duplicate_url`". Both are labelled as history, so they don't conflict with the current rule, but a quick reader could pick up the 409.

2. **Old paging rule still in spec.md, marked as superseded.** `spec.md:18` says "using a limit and an offset, plus the total count. *(Paging superseded by the constitution v1.1.0 session below: next-page token, no offset.)*". The current rule is at `spec.md:23`: "The offset option is removed".

3. **tasks.md says the revision tasks are open, but they are all checked.** `tasks.md:21-22` says "tasks for the revised duplicate rule are open `[ ]`", and `tasks.md:170` says "T012 (tests, confirmed failing) → T015 ...". Yet every one of those tasks is marked done, for example `tasks.md:72` "- [X] T012 ...", `tasks.md:78` "- [X] T015 ...", and the same for T016, T017 and T028 to T030.

4. **One trailing slash or several.** `spec.md:16` says "trailing slash on the path removed", and `spec.md:139` says "a trailing slash on the path". But `research.md:66` says "strip one or more trailing slashes from the path", and `data-model.md:48` says "Remove trailing slashes from the path." The spec reads as singular while the design documents remove several. The material doesn't settle whether `/docs//` and `/docs` are the same link.

5. **Error codes: research.md lists 3, openapi.yaml lists 7.** `research.md:103-104` says "Codes: `validation_error` (422), `not_found` (404), `internal_error` (500)". `contracts/openapi.yaml:135` has "enum: [validation_error, not_found, internal_error, bad_request, method_not_allowed, conflict, http_error]". `tasks.md:220` (T032) says the contract was aligned to these extra codes "(contradicts)", but research.md was not updated to match.

6. **The checklist still says there are no implementation details and that questions are open.** `checklists/requirements.md:9` "[x] No implementation details (languages, frameworks, APIs)" and `:31` "[x] No implementation details leak into specification" conflict with the spec naming HTTP status codes (`spec.md:166` "HTTP 200 OK"). The checklist records this as a deliberate exception at `checklists/requirements.md:38-42`. Separately, `checklists/requirements.md:35-36` still says "The Edge Cases section lists open behavior questions (duplicate handling, ...)", even though those questions are answered in `spec.md:134-151`.

7. **The spec's status doesn't match the later documents.** `spec.md:7` says "**Status**: Draft", while plan.md, research.md and tasks.md treat its revised rules as final and implemented (`tasks.md:78` "- [X] T015 ...").
