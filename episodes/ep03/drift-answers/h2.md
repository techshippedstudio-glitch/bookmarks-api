## Contradictions and inconsistencies between files

None of these changes the answers above. Every current statement in every file agrees on 200 for a duplicate, an unchanged bookmark, and cursor paging. The items below are stale history or small wording differences.

1. **Old duplicate rule (409) is still in the text, but marked as superseded.**
   - `spec.md:17`: "~~Reject it with a conflict error that includes the existing bookmark's identifier; the existing bookmark is left unchanged.~~ Superseded on 2026-10-24"
   - `research.md:41-42`: "this replaced the original 'raise a duplicate error carrying its id', which produced 409"
   - The current rule, in contrast, is in `spec.md:29` and `spec.md:164-166` (200 OK). These are records of the change, not live conflicts.

2. **Offset paging tasks still in tasks.md, marked as history.**
   - `tasks.md:100` (T020): "`offset` (0 or greater, default 0) query parameters"
   - `tasks.md:98` (T018): "`BookmarkPage {items: list[Bookmark], total, limit, offset}`"
   - On the other side, `tasks.md:89-90` says "T017-T020 built offset paging, which Principle VI now forbids ... these tasks are kept as history". `tasks.md:211` (T032) replaces it with keyset paging, and `data-model.md:36` says "`offset` Not accepted". A reader skimming tasks.md alone could be misled.

3. **The quality checklist calls resolved questions "open".**
   - `checklists/requirements.md:35-37`: "The Edge Cases section lists open behavior questions (duplicate handling, link equivalence, ...)... they are the focus for `/speckit-clarify`"
   - But `spec.md:132-150` now states those edge cases as settled behavior, and `research.md:3-4` says "there were no open NEEDS CLARIFICATION markers after `/speckit-clarify`". The checklist is out of date.

4. **Trailing slash: "one" versus "one or more" (small wording gap).**
   - `spec.md:18`: "trailing slash on the path removed" (singular)
   - `research.md:55`: "strip one or more trailing slashes from the path"
   - `data-model.md:48`: "Remove trailing slashes from the path"
   - The spec does not say what happens to a path ending in several slashes. The derived files say all of them are removed. Since spec.md wins, behavior for multiple trailing slashes is not settled by the authoritative document.

5. **Error code list in research.md is shorter than the contract (an omission, not a direct conflict).**
   - `research.md:92-96` names `validation_error` (422), `not_found` (404) and `internal_error` (500).
   - `contracts/openapi.yaml:131`: "enum: [validation_error, not_found, method_not_allowed, internal_error]"
   - `tasks.md:231` (T039) records that `method_not_allowed` was added to the contract later, and research.md was not updated.

6. **Spec status.** `spec.md:7` still says "**Status**: Draft" even though `spec.md:9` declares it authoritative. This is not a behavioral contradiction, but readers may wonder whether it is final.
