## Contradictions between files

1. **Duplicate save: 409 or 200.** 002 says it settles this one.
   - 001 says 409. `001-bookmarks-api/spec.md:15` "Reject it with a conflict error that includes the existing bookmark's identifier". The same rule appears in `001-bookmarks-api/spec.md:44-46`, `:125-127` and `:154-156`, and in `001-bookmarks-api/contracts/openapi.yaml:25-26`: "'409': The normalized link is already bookmarked; details.existing_id names it". It also appears in `001-bookmarks-api/quickstart.md:39`: "409 `duplicate_url`, `details.existing_id` = id from step 1". The task and research files say the same: `001-bookmarks-api/tasks.md:57,64,71` and `001-bookmarks-api/research.md:39-40,87`.
   - 002 says 200. `002-idempotent-duplicate-save/spec.md:100-102`, `002-idempotent-duplicate-save/contracts/openapi.yaml:28-31` and `002-idempotent-duplicate-save/quickstart.md:34`: "200, body identical to step 1".

2. **Concurrent saves of the same new link.**
   - 001 says one save gets 201 and the other gets 409. `001-bookmarks-api/tasks.md:64` "two concurrent saves of equivalent links (two threads) → exactly one 201 and one 409, one row".
   - 002 says one gets 201 and the other gets 200. `002-idempotent-duplicate-save/spec.md:110-111` "exactly one save MUST receive 201 Created and every other MUST receive 200 OK with the same bookmark".

3. **The `duplicate_url` error code.**
   - It exists in 001. `001-bookmarks-api/contracts/openapi.yaml:129` "enum: [validation_error, not_found, duplicate_url, internal_error]".
   - It is removed in 002. `002-idempotent-duplicate-save/contracts/openapi.yaml:134` "enum: [validation_error, not_found, internal_error]".

4. **Paging: offset or cursor.** This conflict is inside 001. Its later clarification and convergence tasks replace offset paging.
   - Offset: `001-bookmarks-api/spec.md:18` "using a limit and an offset, plus the total count". Also `001-bookmarks-api/tasks.md:81-82` "returns saved bookmarks newest first with `total`, `limit` and `offset`" and `001-bookmarks-api/tasks.md:95`, where T020 builds `offset` (0 or greater, default 0).
   - Cursor: `001-bookmarks-api/spec.md:23` "The offset option is removed". Also `001-bookmarks-api/tasks.md:84-85` "T017-T020 built offset paging, which Principle VI now forbids", `001-bookmarks-api/tasks.md:206-208` (T032–T034, cursor paging and 422 for `offset`) and both `openapi.yaml` files, which have only `cursor`.

5. **Trailing slashes (minor wording difference).**
   - Singular: `001-bookmarks-api/spec.md:16` "trailing slash on the path removed".
   - Plural: `001-bookmarks-api/data-model.md:48` "Remove trailing slashes from the path", and `001-bookmarks-api/research.md:49` "strip one or more trailing slashes from the path".
   - The spec could be read as removing only one slash. The design documents remove all of them.

6. **001 is not marked as replaced.** This is a gap rather than a direct conflict. Only 002 says it replaces 001. 001 still shows the 409 rule, both specs say `**Status**: Draft` (`001-bookmarks-api/spec.md:7`, `002-idempotent-duplicate-save/spec.md:7`), and `002-idempotent-duplicate-save/tasks.md:169` says "`specs/001-bookmarks-api/` is a finished historical record: never edit it". A reader who opens only the 001 folder gets the old save behavior.
