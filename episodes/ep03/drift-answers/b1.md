**Contradictions between files**

A. **Duplicate save: 409 conflict (001) vs 200 OK (002).** 002 explicitly says it replaces 001 on this point, and 001 was left unedited on purpose.
- `001-bookmarks-api/spec.md:154-155`: "A save of an existing link MUST be rejected with a conflict error that includes the existing bookmark's identifier". The same rule appears at `001-bookmarks-api/spec.md:15`, `:44-46` and `:125-127`.
- `001-bookmarks-api/contracts/openapi.yaml:25-26`: "'409': description: The normalized link is already bookmarked; details.existing_id names it"
- `001-bookmarks-api/quickstart.md:39`: "409 `duplicate_url`, `details.existing_id` = id from step 1"
- `001-bookmarks-api/tasks.md:56-57`: "saving an equivalent link returns 409 with `details.existing_id`." (also T015, T016 and T026 at lines 70, 71 and 144)
- `001-bookmarks-api/research.md:40`: "look up the existing row and raise a duplicate error carrying its id."
- Against all of these: `002-idempotent-duplicate-save/spec.md:95-96` (200 OK, no conflict), `002-idempotent-duplicate-save/contracts/openapi.yaml:10-11`: "Saving an already bookmarked link no longer returns 409 duplicate_url; it returns the existing bookmark, unchanged, with 200." and `002-idempotent-duplicate-save/quickstart.md:7-8`: "its manual step 2 (409 `duplicate_url`) is superseded by step 2 below."
- One leftover: 001's error enum still lists `duplicate_url` (`001-bookmarks-api/contracts/openapi.yaml:129`). 002 says that code "is no longer produced by saving; it may remain in the shared error format for other uses" (`002-idempotent-duplicate-save/spec.md:139-140`).

B. **List paging: offset vs cursor, inside 001.** 001's own files mark the offset version as replaced.
- `001-bookmarks-api/spec.md:18`: "Return pages: 20 per page by default, up to 100 per page, using a limit and an offset, plus the total count."
- Against it: `001-bookmarks-api/spec.md:23`: "Each page returns an opaque next-page token … The offset option is removed".
- `001-bookmarks-api/tasks.md:81-82`: "`GET /bookmarks` returns saved bookmarks newest first with `total`, `limit` and `offset`." Also T018 to T020 at lines 93-95 build offset paging.
- Against it: `001-bookmarks-api/tasks.md:84-85`: "T017-T020 built offset paging, which Principle VI now forbids. Corrective tasks are appended … these tasks are kept as history." The corrective tasks T032 to T034 (lines 206-208) switch to keyset paging with `next_cursor`.

C. **Trailing slash wording (minor, not a real conflict).** `001-bookmarks-api/spec.md:16` says "trailing slash on the path removed". `001-bookmarks-api/research.md:49` says "strip one or more trailing slashes from the path", and `001-bookmarks-api/data-model.md:48` says "Remove trailing slashes from the path." The spec doesn't say whether more than one slash is removed. The lower-level documents say all of them are.
