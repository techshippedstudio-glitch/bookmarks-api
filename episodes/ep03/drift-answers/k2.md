## Contradictions and inconsistencies found

1. **The full list of error codes differs between files.**
   - research.md:103-104 lists only three codes: "Codes: `validation_error` (422), `not_found` (404), `internal_error` (500)."
   - contracts/openapi.yaml:135 lists seven: "enum: [validation_error, not_found, internal_error, bad_request, method_not_allowed, conflict, http_error]".
   - plan.md:61 sits in between: "validation (422), not found (404) and unexpected (500) ... the generic 409 mapping for framework `HTTPException`s stays in the envelope".
   - tasks.md:220 (T032) admits the mismatch: "Align the `ErrorResponse.error.code` enum ... per plan: contract and FR-010 (contradicts)".
   - This does not affect the answers above.

2. **tasks.md disagrees with itself about the 2026-10-24 work.**
   - tasks.md:21-22 says "tasks for the revised duplicate rule are open `[ ]`", and tasks.md:168-171 has a heading "Open work for the 2026-10-24 revision".
   - But the same tasks are marked done: tasks.md:72 "- [X] T012", tasks.md:78 "- [X] T015", tasks.md:79 "- [X] T016", tasks.md:80 "- [X] T017".
   - The material doesn't say whether the revised duplicate rule has actually been built.

3. **spec.md still contains the replaced rules, but each one is marked as superseded.**
   - Duplicate saves: spec.md:17 "Reject it with a conflict error ... *(Superseded 2026-10-24 ...)*" versus spec.md:29-32 (200 OK).
   - Paging: spec.md:20 "using a limit and an offset, plus the total count. *(Paging superseded ...)*" versus spec.md:25 (token, no offset).
   - research.md:59-61 and tasks.md:214-215 record the old 409 `duplicate_url` behavior only as history.
   - Because of the markings, these are not live contradictions.

4. **One trailing slash or several?** The wording on trailing slashes differs slightly.
   - spec.md:18 and spec.md:141 say "trailing slash on the path removed" / "a trailing slash on the path" (singular).
   - research.md:66 says "strip one or more trailing slashes from the path", and data-model.md:48 says "Remove trailing slashes from the path."
   - The spec doesn't settle whether a link ending in `//` matches the same link with no slash.

5. **The spec is labelled authoritative but is still a draft.** spec.md:9 calls itself the source of truth, while spec.md:7 says "**Status**: Draft". This doesn't conflict with another file, but it weakens the claim somewhat.
